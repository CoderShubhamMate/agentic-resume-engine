# 10 — SECURITY AND CREDENTIALS POLICY FOR AI AGENTS

## 10.1 Purpose and Scope
This policy establishes mandatory security boundaries for AI agents operating in this workspace. 

**Core Principle:** AI agents must NEVER disclose, commit, leak, publish, or log candidate account credentials, portal passwords, session cookies, or private API keys.

These rules apply to all web searches, portal interactions, terminal commands, file creations, git commits, and output logs generated by the agent.

## 10.2 Credential Protection Rules
1. **Never Hardcode Secrets:** Never write passwords, personal authentication tokens, or private secrets into markdown, python, or configuration files tracked by version control.
2. **Environment Variable Isolation:** When interacting with services requiring credentials, use environment variables loaded from a `.gitignore`-protected `.env` file or native OS credential manager.
3. **No Credential Dumping:** If the user provides a password, portal login, or verification token in chat, use it strictly in memory for the immediate authorized action. Never append it to `Master_Data/`, prompts, notes, or git commit messages.
4. **Clean Commits:** Prior to staging or pushing git commits, verify with `git diff` that no personal authentication material, private tokens, or sensitive host paths are being added.

## 10.3 Authorized Portal Operations
When authorized by the user to interact with job application portals:
- Act only on the candidate's explicit behalf.
- Review eligibility and job requirements factually.
- Submit only verified information matching `Master_Data/`.
- Never attempt to bypass authentication boundaries, solve CAPTCHAs via unsanctioned workarounds, or access unauthorized administrative endpoints.
